# Component Designs

Detailed design documents for individual subsystems live in this directory, sequenced to match the vertical-slice milestones in [docs/requirements.md](../requirements.md) §6. Each component design should be reviewed and marked **`Approved`** before implementing its milestone.

## Component Specs (Milestone Order)
1. **[`1a-backend-ingestion-and-security.md`](1a-backend-ingestion-and-security.md)** *(Milestone 1a — **Approved** 2026-11-24, **Implemented** 2026-11-25; implementation **Approved** 2026-11-25; user-test fixes `E-01`–`E-13` **Approved** 2026-11-27)* — Docker Compose stack, Alembic schema, Postgres job queue (`SKIP LOCKED`, dedupe, leases, advisory-lock scheduler), cron-friendly `worker run-once` batch CLI, `pipeline_runs`/`stage_metrics` timing instrumentation, per-device pairing auth + `Host`/CORS middleware, shared `SafeHttpClient` SSRF protection, polite polling (`ETag`/`Last-Modified`/`301`/`410`/`429`), isolated full-text extraction, backfill cap (`N=10`), expiration sweeper, and backup/restore scripts.
2. **[`1b-sync-protocol-and-search.md`](1b-sync-protocol-and-search.md)** *(Milestone 1b — **Approved** 2026-11-25, **Implemented & Implementation Approved** 2026-11-25; residual risks `RR-1`/`RR-2` accepted)* — Commit-ordered `sync_changes` watermark, stateless cursor-paginated `/api/v1/sync/bootstrap`, coalesced `/api/v1/sync/pull` with `pruned_through_seq` / `instance_epoch` recovery, single-transaction `/api/v1/sync/push` with deterministic value-rank LWW tie-breaking, bounded `ingest_sync_seq` bulk mark-read, online `/api/v1/settings`, and PostgreSQL FTS search with structured XSS-safe snippets.
3. **[`1c-client-ui-and-offline-shell.md`](1c-client-ui-and-offline-shell.md)** *(Milestone 1c — **Approved** 2026-11-25, **Implemented & Implementation Approved** 2026-11-25; user-test fixes **Approved** 2026-11-27; `forceFullResync()` lock carried forward to `1d-ops`)* — Localhost-served React + TypeScript + Tailwind CSS v4 + Dexie.js SPA (Python stdlib `localhost:4180` runner + systemd user unit + `.desktop` launcher + Nginx LAN fallback), Service Worker offline shell, `navigator.storage.persist()`, server-base + overlay outbox + 48h replay journal + rejection rollback UX, detached MiniSearch local search, classic 3-pane/list UX with sortable headers & keyboard shortcuts, single-pass DOMPurify + remote image blocking + strict CSP, and System Health & Pipeline Performance Metrics UI.
4. **[`1d-ops-setup-and-cli.md`](1d-ops-setup-and-cli.md)** *(Sub-milestone `1d-ops` — **Approved** 2026-11-27)* — Pre-`1d` carry-forward slice resolving `E-09` (idempotent `make setup` / `scripts/setup-server.sh` + `smartrss-worker.{service,timer}`), `E-11` (shared `smartrss.feeds.service`, `smartrss feeds add|list|import-opml|export-opml` CLI, and mode-`0600` OPML snapshot + rotation in `scripts/backup.sh`), and the `1c` carry-forward (locked & fenced `SyncEngine.forceFullResync()`).
5. **`1d-llm-adapter-and-enrichment.md`** *(Milestone 1d)* — `LLMAdapter` runtime contract (`Ollama` & `llama.cpp`), structured JSON output, `<think>` handling, phase timing capture (`prompt_eval_ms`/`generation_ms`/tok/s), token budgets, prompt instruction precedence & delimitation (including per-feed `curation_instructions` and active `feed_instruction` notes), 5-tier relevance rubric, seeded/versioned prompt & Interest Profile editor, concurrency/priority/cron-window/quiet-hours controls, and `live_llm` MoE smoke benchmark.
6. **`1e-deduplication-and-clustering.md`** *(Milestone 1e)* — Versioned `item_embeddings`, canonical `title + lead_excerpt` embedding pipeline, pre-enrichment URL & cosine-similarity clustering, merge/split semantics, grouped cluster UI, and "Mark cluster read" / "Split from cluster".
7. **`1f-mini-research-and-pdfs.md`** *(Milestone 1f)* — Isolated PyMuPDF/HTML extractor limits, primary-source link heuristics, per-feed `research_policy` & guardrails, on-demand "Dig Deeper" & "Fetch PDFs here" workflow, and synthesized primary-source context.
8. **`1g-feedback-and-evaluation.md`** *(Milestone 1g)* — Explicit item feedback UI/storage, inline offline-capable per-feed written instruction notes (`feed_instruction`) + promote/archive workflow, same-feed prioritized diverse/bounded calibration example selection, optional per-feed unread re-enrichment, and offline relevance evaluation harness (`live_llm`) measuring tier alignment across prompt/profile/feed-instruction/model versions.
